# The Harness That Earns Its Edits

Задача хакатона: **Statement 1 — Recursive Harnessing** (обвязка переписывает саму себя),
с задеванием **Statement 2 — Long Horizon** (память всех прогонов + обучение по жёстким метрикам).

Полигон: перевод вопроса на естественном языке в запрос MongoDB по `sample_mflix`.
Метрика: доля вопросов из отложенного набора, где результат запроса совпал с эталоном.
Сигнал двоичный, без человеческой оценки — самообман виден сразу.

## Что обвязка крутит в себе сама

Версия обвязки — документ в Mongo (`harness.versions`):

- `system_prompt` — базовый промпт (стартовый = официальный промпт MongoDB из доков NL→MQL)
- `rules[]` — правила авторинга запросов (стартовые = девять правил MongoDB)
- `cot` — включён ли пошаговый разбор перед генерацией
- `sample_docs_n` — сколько образцовых документов подкладывать в контекст
- `include_indexes` — показывать ли индексы коллекции
- `retrieve_k` — сколько похожих прошлых провалов поднимать из памяти
- `tools[]` — разрешённый набор инструментов (find / aggregate / count / schema / mcp)

## Ворота (то, ради чего всё)

Правка версии N+1 не применяется сама по себе:

1. прогон кандидата и текущей версии на **отложенном** наборе вопросов;
2. выигрыш должен превышать шум (не «стало 7 из 10», а значимо на достаточной выборке);
3. **отказ уровня архитектуры**: нельзя расширить `tools[]` и нельзя тронуть guardrails —
   это проверяет конверт, живой отказ, а не правило в промпте;
4. решение пишется в `harness.edits` вместе с причиной: `promoted` / `rejected_outsample` /
   `rejected_envelope` / `rejected_insignificant`;
5. откат — одной командой, указатель на предыдущую версию.

Демо показывает обе отбраковки: переобучение на обучающем наборе и попытку выдать себе
лишние инструменты. Это и есть «самоулучшение, которое не может себя обмануть».

## Схема в Atlas

- `runs` — прогон: версия обвязки, набор вопросов, счёт, время
- `steps` — шаг внутри прогона: вопрос, сгенерированный запрос, результат, вердикт
- `lessons` — урок с провала, с **автоматическими эмбеддингами** (векторный поиск в памяти)
- `versions` — версии обвязки, полный конфиг + отпечаток
- `edits` — журнал правок: предложение, доказательства, решение, причина, откат
- `fetches` — журнал сырья с провенансом: что спросили, хеш ответа, секреты вырезаны

Векторный поиск — по памяти провалов. Atlas Search — по ключевым словам и названиям коллекций.

## Демо на 3 минуты

1. прогон слабой версии — счёт виден;
2. обвязка предлагает три правки; две отбракованы (одна — переобучение, вторая — попытка
   расширить инструменты), третья проходит;
3. повторный прогон на отложенных вопросах — счёт растёт;
4. откат одной командой, причина отказа читается из журнала.

## Бюджет времени (около 5 часов)

- 1:00 — подключение к Atlas, схема, загрузка sample_mflix, набор эталонных вопросов
- 1:30 — ядро: прогон, измеритель, запись прогонов и шагов
- 1:00 — память провалов (эмбеддинги + векторный поиск) и предлагатель правок
- 0:45 — ворота, конверт, журнал правок, откат
- 0:45 — сценарий демо, минута видео, README

## Правила хакатона, которые нельзя нарушить

- **Только новая работа**: репозиторий не должен содержать кода до события.
  ARLI и ENSO — источник идей, их код в проект не тащим.
- **Обязателен Atlas** (песочница с инвайтом) — без него в финал не пускают.
- Публичный репозиторий + видео на 1 минуту со звуком + краткое описание.
- Дашборд не может быть главной фичей: сцену делает терминальное демо.
